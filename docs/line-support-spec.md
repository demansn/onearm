# ТЗ: поддержка линий из Figma (компонент `Line`)

Статус: реализовано 2026-10-01. План и ход работ: `plans/line-support-plan.md` (папка в `.gitignore`, в репозиторий не попадает). Дата ТЗ: 2026-09-30. Исполнитель: движок onearm (экспортёр `tools/figma` и `modules/engine`).
Источник данных: файл Figma Candy Splash (`ONStH8eR1p8KD73HMnOmYG`), конфиг `assets/components.config.json`.

## 1. Проблема

Линии, нарисованные в Figma, не появляются в игре. Ошибок при этом нет ни в экспортёре, ни в движке.

Линии в макетах бывают двух видов, и оба ломаются по-разному.

| Узел Figma | Сколько в файле | Что попадает в конфиг | Что строит движок |
|---|---|---|---|
| `LINE` (инструмент Line) | 46 видимых в компонентах | `{"type":"LINE","x","y"}` без стиля и размеров | пустой `BaseContainer` |
| `VECTOR` только с обводкой, вырожденный по высоте («Line 3» в `AutoplaySettingsPopup`, `MessagePopup`) | 8 | `{"type":"Graphics","x","y","style":{stroke,strokeWidth}}` без размеров | пустой `PIXI.Graphics` |

Причины:

1. **`LINE` не описан в экспортёре.** Его нет в `NODE_TYPE_MAPPING` (`tools/figma/src/extractors/nodeUtils.ts`) и нет в `switch` метода `processBaseNode` (`tools/figma/src/core/NodeProcessor.ts`). Поэтому тип уходит как есть, а стиль не извлекается.
2. **Stroke-only `VECTOR` выгружается без геометрии.** В `processBaseNode` вектор с заливкой превращается в `Rectangle` по bounding box. Вектор только с обводкой остаётся `Graphics`, и длина линии теряется.
3. **Движок молча глотает неизвестные типы.** `LayoutBuilder.buildComponent` подставляет `BaseContainer`, если фабрики для типа нет. Фабрика `Graphics` вызывает `new PIXI.Graphics(props)`, который игнорирует `style` и ничего не рисует.
4. **Одного движка недостаточно.** В конфиге для `LINE` нет ни цвета, ни толщины, ни длины. Исправление обязано начаться с экспортёра.

Что уже проверено на реальных данных:

- Все 54 линии прямые, горизонтальные, сплошные, без пунктира, без поворота, с solid-обводкой.
- Иконки из обводок (`HomeIcon`, `LinkIcon`) в конфиг не попадают: они экспортируются картинками. Этот ТЗ их не касается.
- В конфиге candy_splash нет ни одного `Ellipse`. В конфиге gates-of-olympus нет ни `LINE`, ни `Graphics`, ни `Ellipse`.

## 2. Цель и объём

**Цель.** Прямая линия из Figma рисуется в игре с тем же положением, длиной, углом, цветом, толщиной и формой концов, что и в макете.

**В объёме:**

- Узел `LINE` с любым углом поворота.
- Узел `VECTOR` только с обводкой, у которого одна из сторон `size` равна нулю. Это прямой горизонтальный или вертикальный отрезок, нарисованный пером.
- Новый объект движка `Line` и его регистрация в фабрике.
- Предупреждения о неподдержанных узлах в экспортёре и в движке.

**Вне объёма.** Каждый такой случай экспортёр должен сопровождать предупреждением, а не молча портить.

- Кривые, ломаные, стрелки, звёзды, boolean-фигуры и любые произвольные пути.
- Диагональный отрезок, нарисованный пером как `VECTOR`. Без запроса геометрии его нельзя отличить от кривой. Для наклонных линий дизайнер использует инструмент Line.
- Пунктир (`strokeDashes`).
- Градиентная обводка.
- Стрелки на концах (`strokeCap` вида `ARROW_*`, `TRIANGLE_*`, `CIRCLE_FILLED`, `DIAMOND_FILLED`).
- Изменение длины в рантайме и растяжение по constraints, AutoLayout или ширине ScrollBox.
- Запрос `geometry=paths`. Он увеличивает ответ Figma с 2,8 до 7,7 МБ на этом файле и замедляет watch-режим.
- Поведение векторов с заливкой, которые сейчас выгружаются как `Rectangle`. Оно не меняется.
- Регистрация фабрики `Graphics`. Она остаётся как есть.

Формат спроектирован так, чтобы произвольные пути можно было добавить позже отдельным типом, не трогая `Line`.

## 3. Формат конфига

```json
{
  "name": "Line 3",
  "type": "Line",
  "x": 66,
  "y": 187.5,
  "length": 270,
  "angle": 0,
  "style": {
    "stroke": "rgba(13,167,182,1)",
    "strokeWidth": 3,
    "cap": "butt"
  }
}
```

| Поле | Обязательное | Смысл |
|---|---|---|
| `x`, `y` | да | Начало отрезка в координатах родителя. Точка лежит на оси обводки, обводка симметрична относительно оси. Дробные значения допустимы, округление до 2 знаков. |
| `length` | да | Длина отрезка в пикселях, больше нуля. |
| `angle` | нет | Поворот в градусах по часовой стрелке, как у остальных объектов движка (`object.angle`). Не пишется, если равен нулю. |
| `style.stroke` | да | Цвет в формате `rgba(r,g,b,a)`, как у `Rectangle`. Альфа учитывает `opacity` самой обводки. |
| `style.strokeWidth` | да | Толщина, больше нуля, округление до 2 знаков. |
| `style.cap` | нет | `butt`, `round` или `square`. По умолчанию `butt`. |
| `alpha`, `visible` | нет | Общие свойства объекта, как у остальных узлов. Прозрачность узла идёт в `alpha` объекта, а не в стиль. |

Выравнивание обводки в конфиг не выгружается. Движок всегда рисует обводку по центру оси, а экспортёр переносит ось так, чтобы полоса совпала с Figma. Так движок остаётся простым, а все особенности Figma живут в одном месте.

## 4. Экспортёр (`tools/figma/src`)

### 4.1. Адаптер узла

Интерфейс `AbstractNode` (`adapters/types.ts`) и его единственная реализация `RestNodeAdapter` (`adapters/rest/RestNodeAdapter.ts`) получают новые поля:

- `size` — `{ x, y }`, размер узла без учёта поворота.
- `relativeTransform` — матрица `[[a, c, tx], [b, d, ty]]`.
- `strokeCap`, `strokeAlign`, `strokeDashes`.
- `preciseBounds` — bounding box относительно родителя без округления (нужен для дробных координат).

**Отклонение от первоначального ТЗ.** Обычный ответ REST (`GET /v1/files/:key`) не содержит `size` и `relativeTransform`: они приходят только с `geometry=paths`, а этот запрос в пайплайн не включён (§2). Поля в адаптере опциональны и заполняются, если есть в ответе. Реальная геометрия строится из `rotation` и `absoluteBoundingBox` (см. §4.3).

### 4.2. Маппинг и определение линии

1. В `NODE_TYPE_MAPPING` добавить `LINE → Line`.
2. `VECTOR` становится `Line`, если выполнены все условия:
   - нет видимых заливок;
   - есть ровно одна видимая обводка;
   - `size.x === 0` или `size.y === 0`.
3. Stroke-only `VECTOR`, не подошедший под условия, остаётся `Graphics`, и экспортёр пишет предупреждение.

### 4.3. Геометрия

Реализовано чистой функцией `computeLineGeometry` (`tools/figma/src/core/lineGeometry.ts`, тесты рядом, `npm run test:figma`). Положение берётся из bounding box, уже приведённого к координатам родителя, поэтому разбираться, относительно чего Figma считает `relativeTransform` у детей `GROUP`, не нужно.

Источник направления и длины зависит от того, что пришло от REST:

- **Обычный ответ (без `size` и `relativeTransform`).**
  - `LINE`: ось `u = (cos r, sin r)`, нормаль `n = (-sin r, cos r)`, где `r` — `rotation` в радианах (по часовой, как в PIXI). Длина `hypot(bbox.width, bbox.height)`: толщина обводки в bounding box у `LINE` не входит.
  - Прямой `VECTOR`: bounding box вырожден по одной оси. Если вырождена высота, отрезок горизонтальный (`u = (1, 0)`, длина `bbox.width`); если ширина, вертикальный (`u = (0, 1)`, длина `bbox.height`). Обводка `VECTOR` симметрична, поэтому `rotation` не используется. Если bounding box не вырожден ни по одной оси, узел не считается линией.
- **При наличии `size` и `relativeTransform`** (`geometry=paths`) работает исходный алгоритм: `u = (a, b)`, `n = (c, d)`; для вертикального `VECTOR` с `size.x === 0` ось и нормаль меняются местами; длина `size.x` (для вертикального `VECTOR` `size.y`).

Дальше общие правила:

1. **Угол.** `angle = atan2(u.y, u.x)` в градусах, округление до 0,1; `-180` приводится к `180`.
2. **Начало отрезка.** `start.x = bbox.x`, если `u.x ≥ 0`, иначе `bbox.x + bbox.width`; аналогично `y` по `u.y`. Используется `preciseBounds`, без округления.
3. **Нулевая длина** (меньше `0,001`) даёт отказ с причиной, узел пропускается с предупреждением.
4. **Сдвиг полосы обводки к центру.** Figma кладёт обводку по-разному:
   - `LINE` с `strokeAlign: CENTER` рисуется целиком по одну сторону оси, в диапазоне `[-w, 0]` по нормали. Пример: при толщине 3 `absoluteRenderBounds` на 3 px выше bounding box. Поэтому `start += n * (-w / 2)`. Правило выведено из данных файла (`absoluteRenderBounds`) и напрямую по `strokeGeometry` не проверялось.
   - `VECTOR` с `strokeAlign: CENTER` рисуется симметрично, в диапазоне `[-w/2, w/2]`. Подтверждено на `MessagePopup`, узел `5086:1240`: `strokeGeometry` `M0 0L0 1.5L385 1.5L385 0L385 -1.5L0 -1.5L0 0Z` при толщине 3. Сдвиг не нужен.
   - `INSIDE` и `OUTSIDE` не проверены ни для `LINE`, ни для `VECTOR`. Экспортёр выдаёт предупреждение и считает выравнивание как `CENTER` (`alignWarning`).
5. **Округление.** `x`, `y`, `length`, `strokeWidth` округляются до 2 знаков, а не до целых. Линия толщиной 3 с центром на 107,5 после округления до 108 станет размытой. Дробные координаты обеспечивает `preciseBounds` в адаптере: существующие `x/y` по-прежнему округляются до целых, чтобы не менять выгрузку других типов. `LayoutBuilder.applyProperties` и `applyDisplayProperties` дробные значения не округляют (проверено рендером).
6. **Поворот.** `correctRotatedPosition` к `Line` не применяется: `x`, `y`, `angle` из `computeLineGeometry` перезаписывают значения из `extractCommonProps`. Он рассчитан на прямоугольник с ненулевой высотой.

### 4.4. Стиль

- Цвет из первой видимой solid-обводки через `colorToHex`. Альфа равна `color.a * paint.opacity`. `extractStrokeProps` `opacity` обводки по-прежнему игнорирует: для `Line` он учитывается только в `lineExtractor`, остальные типы не менялись (иначе поменялся бы экспорт gates-of-olympus).
- `strokeCap`: `NONE` или отсутствие даёт `butt`, `ROUND` даёт `round`, `SQUARE` даёт `square`. Любое другое значение даёт `butt` и предупреждение.
- `strokeWidth` берётся без `Math.round`, в отличие от текущего `extractStrokeProps`.
- `opacity` узла идёт в `alpha` объекта, как сейчас.

### 4.5. Предупреждения экспортёра

Использовать существующий механизм `warnings` в `ExportPipeline`: вывод в консоль и `metadata.warnings` в конфиге. Каждое предупреждение содержит путь до узла и причину.

| Ситуация | Что выгружается |
|---|---|
| Тип узла без маппинга: `STAR`, `POLYGON`, `REGULAR_POLYGON`, `BOOLEAN_OPERATION` и любой новый | как сейчас |
| Stroke-only `VECTOR`, не прямой горизонтальный или вертикальный | `Graphics`, как сейчас |
| Линия с пунктиром | `Line` без пунктира |
| Линия с градиентной обводкой | `Line` цветом первого стопа |
| Линия со стрелкой на конце | `Line` с `cap: butt` |
| Линия без видимой обводки или с нулевой длиной или толщиной | узел пропускается |
| `strokeAlign` не `CENTER`, пока не проверен | `Line` как с `CENTER` |

### 4.6. Схема и документация экспортёра

- В `schema/components-config.schema.ts` в раздел Graphics добавить `LineConfig` и включить его в объединение дочерних типов.
- В `docs/figma-mapping-v2.md` §8.3 отметить, что `LINE` и прямые stroke-only векторы идут в `Line`, а план «`VECTOR` → `graphics`» относится только к произвольным путям.
- Пересобрать `tools/figma/dist/cli.js` командой `npm run build:figma`. Игры вызывают именно собранный файл.

## 5. Движок (`modules/engine`)

### 5.1. Класс `Line`

Файл `common/displayObjects/Line.js`, класс `Line extends Graphics`. Устроен по образцу `Rectangle`.

- Конструктор принимает `{ name, length, style }` и сразу вызывает `redraw()`.
- `redraw()` делает `clear()`, затем `moveTo(0, 0)`, `lineTo(length, 0)` и `stroke({ width, color, cap, alignment })`. Используется `alignment: 0.5`. Проверено рендером в PixiJS 8.18: при оси на 100 и толщине 20 полоса занимает 90–110; `0` кладёт полосу вниз от оси, `1` вверх.
- Цвет-строка `rgba(...)` передаётся в PixiJS как есть: альфу PixiJS переносит в обводку сама, парсер не нужен.
- Сеттеры `strokeColor` и `strokeWidth` вызывают перерисовку только при изменении значения, как у `Rectangle`. Геттеры `length`, `strokeColor`, `strokeWidth` возвращают текущие значения.
- Сеттеров `length`, `width` и `height` нет. Растяжение вне объёма.
- Конструктор бросает `Error` с именем объекта, если `length` или `strokeWidth` не положительные числа или нет `style.stroke`. Экспортёр такие узлы не выгружает, значит это ошибка ручного конфига.

### 5.2. Регистрация

- `common/displayObjects/addObjects.js`: `ObjectFactory.registerObjectConstructor("Line", Line)`.
- `index.js`: экспорт `Line` рядом с `Rectangle`.
- `VerticalLine` не трогать. Это отдельный класс с другим контрактом, и он используется напрямую из кода.

### 5.3. Предупреждение о неизвестном типе

В `services/LayoutBuilder.js`, в ветке, где `buildComponent` подставляет `BaseContainer` вместо незарегистрированного типа, при `process.env.NODE_ENV === "development"` писать `console.warn` с именем узла и типом. Поведение в production не меняется.

Реализовано: коммит `d270ff2`. Намеренные подмены перечислены в allowlist `INTENTIONAL_CONTAINER_TYPES = { ReelsFrame }` (невидимый маркер, который `HUDScene` ищет через `findAll`). Срабатывания без allowlist при прогоне обеих игр: candy_splash — `ReelsFrame` (реальный проход), `SoundOn` и `SoundOff` (только синтетическая сборка, из неиспользуемого `SoundToggle`); gates-of-olympus — ни одного. `Ellipse` предупреждает, фабрики для него нет, в allowlist он не включён. С allowlist реальные проходы обеих игр чистые. `ReelsFrame` специфичен для игры, вынос allowlist в `GameConfig` возможен отдельной задачей.

## 7. Риски и открытые вопросы

- **Смещение `LINE` на пол-толщины.** Правило `[-w, 0]` выведено из данных файла (`absoluteRenderBounds`) и напрямую по `strokeGeometry` не проверялось. Для `VECTOR` с `CENTER` симметричность подтверждена на `MessagePopup` (§4.3 п. 4). `INSIDE` и `OUTSIDE` не проверены.
- **Масштаб толщины в инстансах.** Инстанс со `scale` масштабирует `Graphics` целиком, поэтому толщина растёт вместе с длиной. Так же ведёт себя Figma при масштабировании инстанса. При неравномерном `scale` вида `{ x, y }` наклонная линия исказится иначе, чем в Figma. В текущих данных это не встречается и не проверялось.
- **Дробные координаты.** Реализовано через `preciseBounds` в адаптере; `LayoutBuilder.applyProperties` и `applyDisplayProperties` дробные `x/y` не округляют (проверено рендером).
- **Hit area.** `Graphics` без заливки интерактивности не даёт. Линии и не должны быть кликабельными.
- **Открыто: двойное вычитание координат у детей `GROUP`.** Для остальных детей `GROUP` `extractCommonProps` вычитает `group.x/y` из координат, которые адаптер уже сделал относительными группы. Для `Line` это обойдено (`preciseBounds` уже относительны родителя). Не подтверждено и не опровергнуто: ни одна линия candy_splash не лежит в `GROUP`, а правка поменяла бы конфиги игр. Отложено.
